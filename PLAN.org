* v0.1 — Fixed-Width Wire Structures [COMPLETE]

** Goal
   Racket-native DSL for binary wire protocol specification.
   Two layers: data-driven field descriptors + ~struct/wire~ macro surface syntax.
   Scope: byte-aligned, fixed-width fields with configurable endianness.

** Architecture

*** Layer 1: Data-Driven Protocol Descriptors
    Core data structures describing binary layouts:
    - ~field-desc~: name, type, width (bytes), endianness
    - ~protocol-desc~: name, list of field-desc, total size
    - Field types: ~'uint~, ~'sint~, ~'alpha~ (fixed-width ASCII), ~'octets~ (raw bytes)
    - Endianness: ~'big~, ~'little~ (per-field or protocol-wide default)

*** Layer 2: Codec
    Given a ~protocol-desc~, produce:
    - ~encode~: hash of name→value → bytes
    - ~decode~: bytes (+ offset) → hash of name→value
    - ~decode-field~: bytes + offset + field-desc → single value

*** Layer 3: Macro Surface Syntax (~struct/wire~)
    #+begin_src racket
    (struct/wire udp-header
      #:byte-order big
      (src-port  uint 2)
      (dst-port  uint 2)
      (length    uint 2)
      (checksum  uint 2))
    #+end_src
    Generates:
    - ~udp-header~ — protocol-desc value + match expander
    - ~udp-header?~ — predicate
    - ~udp-header-encode~ — keyword args → bytes
    - ~udp-header-decode~ — bytes → zero-copy struct instance
    - ~udp-header-src-port~, etc. — lazy field accessors
    - Match patterns: ~(udp-header #:dst-port dp)~

** Modules

   | File                              | Purpose                              |
   |-----------------------------------+--------------------------------------|
   | ~wirey/field.rkt~                 | field-desc struct, type predicates   |
   | ~wirey/protocol.rkt~              | protocol-desc struct, validation     |
   | ~wirey/codec.rkt~                 | Generic encode/decode/decode-field   |
   | ~wirey/syntax.rkt~                | struct/wire macro                    |
   | ~wirey/main.rkt~                  | Re-exports public API                |
   | ~wirey/protocols/itch.rkt~        | ITCH 5.0 message definitions         |
   | ~wirey/protocols/pcap.rkt~        | PCAP global + record headers         |
   | ~wirey/protocols/ethernet.rkt~    | Ethernet frame header                |
   | ~wirey/protocols/udp.rkt~         | UDP header                           |

* v0.2 — Bitfields

** Goal
   Support sub-byte fields so we can describe IPv4 and TCP headers,
   where fields like ~version~ (4 bits), ~ihl~ (4 bits), ~flags~ (3 bits),
   and ~fragment-offset~ (13 bits) don't fall on byte boundaries.

** Design

*** New field width unit
    Bitfields need widths in bits rather than bytes. Introduce a
    ~#:unit~ option (defaulting to ~bytes~ for backward compatibility):
    #+begin_src racket
    (struct/wire ipv4-header
      #:byte-order big
      (version          uint 4 #:unit bits)
      (ihl              uint 4 #:unit bits)
      (dscp             uint 6 #:unit bits)
      (ecn              uint 2 #:unit bits)
      (total-length     uint 2)
      (identification   uint 2)
      (flags            uint 3 #:unit bits)
      (fragment-offset  uint 13 #:unit bits)
      (ttl              uint 1)
      (protocol         uint 1)
      (header-checksum  uint 2)
      (src-ip           uint 4)
      (dst-ip           uint 4))
    #+end_src

*** Bit-level codec
    - Bitfields are packed MSB-first within their containing byte(s),
      matching network byte order convention (the way IPv4/TCP define them).
    - A bitfield group is a contiguous run of bit-width fields. The group
      must sum to a whole number of bytes (enforced at definition time).
    - Encoding: accumulate bits into a buffer, flush to bytes at group boundary.
    - Decoding: read the byte span, extract bits via shift and mask.

*** Validation
    - Bitfield groups must sum to 8·N bits (no partial bytes).
    - Mixing byte-width and bit-width fields within the same byte is an error
      (bitfields must be grouped together to form complete bytes).
    - A bitfield's value must fit within its bit width.

*** Impact on existing code
    - ~field-desc~ gains an optional unit (~'bytes~ or ~'bits~), defaulting to ~'bytes~.
    - ~protocol-desc-total-size~ must account for bitfield groups.
    - ~encode~/~decode~/~decode-field~ extended with bit-level read/write.
    - All existing byte-aligned code continues to work unchanged.

** Target protocols
   - IPv4 header (20 bytes fixed, bitfields in bytes 0-1 and 6-7)
   - TCP header (20 bytes fixed, bitfields in bytes 12-13)

* v0.3 — Variable-Length Fields and Dependent Lengths

** Goal
   Support fields whose length is determined by the value of another field,
   enabling protocols with variable-length regions (IPv4/TCP options,
   PCAP packet data, TLV structures).

** Design

*** Dependent length expressions
    A field's width can reference another field's decoded value:
    #+begin_src racket
    (struct/wire pcap-packet
      #:byte-order little
      (ts-sec    uint 4)
      (ts-usec   uint 4)
      (incl-len  uint 4)
      (orig-len  uint 4)
      (data      octets (field-ref incl-len)))
    #+end_src

    ~(field-ref incl-len)~ means "the width of ~data~ is the decoded value
    of the ~incl-len~ field." The referenced field must appear before the
    dependent field.

*** Computed width expressions
    For IPv4 options, the length is derived from a field value:
    #+begin_src racket
    (struct/wire ipv4-header-full
      #:byte-order big
      (version     uint 4 #:unit bits)
      (ihl         uint 4 #:unit bits)
      ...
      (dst-ip      uint 4)
      (options     octets (compute (* (- (field-ref ihl) 5) 4))))
    #+end_src

    ~(compute expr)~ allows arithmetic on field references.

*** Impact on total-size
    - ~protocol-desc-total-size~ returns the fixed portion only when
      variable-length fields are present.
    - Add ~protocol-desc-fixed-size~ for the guaranteed minimum.
    - Actual message size is known only after decoding the length fields.

*** Encoding changes
    - Variable-length fields require the encoder to know the actual data length.
    - The encoder validates consistency: if ~incl-len~ is 64, ~data~ must be
      64 bytes. Raise an error on mismatch.

*** Decoding changes
    - Decode fields sequentially. When a variable-length field is reached,
      evaluate its length expression using already-decoded field values.
    - The zero-copy decode instance stores the computed field boundaries.

** Target protocols
   - PCAP packet (header + variable-length captured data)
   - IPv4 with options
   - TCP with options

    - Backward compatible: integer widths still work

*** DONE Step 2: Validation of dependent fields

*** DONE Step 3: Variable-length encoding

* v0.4 — Protocol Composition

** Goal
   Compose wire structures into layered protocol stacks, so a single
   decode call can peel through Ethernet → IPv4 → TCP and provide
   access to each layer's fields.

** Design

*** Layer stacking
    Define a protocol stack as a sequence of wire structures where
    each layer's payload contains the next:
    #+begin_src racket
    (define-stack tcp/ip-stack
      ethernet-header
      #:dispatch ethertype
      [(#x0800)
       ipv4-header
       #:dispatch protocol
       [(6)  tcp-header]
       [(17) udp-header]])
    #+end_src

*** Dispatch on field values
    Each layer boundary includes a dispatch expression that examines
    a field from the current layer to determine which wire struct
    to decode next. This is essentially pattern matching on the wire.

*** Decoded stack value
    The result of decoding a stack is a nested structure where each
    layer is accessible:
    #+begin_src racket
    (define pkt (tcp/ip-stack-decode raw-bytes))
    (ethernet-header-ethertype (stack-layer pkt 'ethernet-header))
    (ipv4-header-src-ip (stack-layer pkt 'ipv4-header))
    (tcp-header-dst-port (stack-layer pkt 'tcp-header))
    #+end_src

*** Match on stacks
    Extend match patterns to work across layers:
    #+begin_src racket
    (match (tcp/ip-stack-decode raw-bytes)
      [(tcp/ip-stack
        (ethernet-header #:ethertype #x0800)
        (ipv4-header #:src-ip src)
        (tcp-header #:dst-port 80))
       (printf "HTTP from ~a\n" src)])
    #+end_src

*** Offset threading
    Each layer computes its payload offset from its own header size.
    The next layer's decode begins at that offset. Variable-length
    headers (IPv4 with IHL, TCP with data-offset) use the header
    length field to compute the payload start.

** Target protocols
   - Ethernet → IPv4 → TCP stack
   - Ethernet → IPv4 → UDP stack
   - PCAP file → packet → Ethernet → ... (full pcap parsing)

* v0.5 — Computed Fields

** Goal
   Support fields whose values are computed from other fields rather than
   provided directly. Primary use case: checksums (IPv4 header checksum,
   TCP/UDP checksum with pseudo-header).

** Design

*** Computed field declaration
    #+begin_src racket
    (struct/wire ipv4-header
      #:byte-order big
      ...
      (header-checksum  uint 2 #:compute ipv4-checksum)
      ...)
    #+end_src

    ~#:compute~ names a function that receives the partially-encoded
    bytes and returns the field's value. The function signature:
    #+begin_src racket
    ;; ipv4-checksum : bytes -> exact-nonneg-integer?
    ;; Receives the fully-encoded header with the checksum field zeroed.
    ;; Returns the one's complement checksum.
    #+end_src

*** Encoding with computed fields
    Two-pass encoding:
    1. Encode all fields, using zero for computed fields.
    2. For each computed field, call its function with the buffer,
       then write the result into the appropriate offset.

*** Decoding with computed fields
    Computed fields decode normally (they're just uint/sint on the wire).
    Optionally, a ~#:validate~ flag can verify the checksum on decode
    and raise an error or warning on mismatch.

*** Checksum library
    Provide common checksum implementations:
    - ~ipv4-header-checksum~: one's complement sum of 16-bit words
    - ~internet-checksum~: generalized for TCP/UDP pseudo-header

** Target protocols
   - IPv4 header checksum
   - UDP checksum (with pseudo-header, optional in IPv4)
   - TCP checksum (with pseudo-header)

* v0.6 — Message Dispatch

** Goal
   Route incoming bytes to the correct wire struct based on a
   discriminator field. Primary use case: ITCH 5.0 message type
   byte determines which of ~20 message formats to decode.

** Design

*** Dispatch declaration
    #+begin_src racket
    (define-dispatch itch-message
      #:on message-type
      #:offset 0
      #:width 1
      #:type alpha
      [("S") itch-system-event]
      [("A") itch-add-order]
      [("F") itch-add-order-mpid]
      [("E") itch-order-executed]
      [("D") itch-order-delete]
      [("P") itch-trade])
    #+end_src

*** Dispatch decoding
    #+begin_src racket
    (define msg (itch-message-decode raw-bytes))
    ;; msg is one of the wire struct types
    (cond
      [(itch-system-event? msg) ...]
      [(itch-add-order? msg) ...]
      ...)
    #+end_src

*** Integration with match
    #+begin_src racket
    (match (itch-message-decode raw-bytes)
      [(itch-add-order #:stock sym #:price p #:shares s)
       (printf "Order: ~a ~a @ ~a\n" sym s p)]
      [(itch-trade #:stock sym #:price p)
       (printf "Trade: ~a @ ~a\n" sym p)])
    #+end_src

    This works naturally because each wire struct already has its
    own match expander — dispatch just selects which one applies.

*** Performance
    The discriminator is read once (a single byte for ITCH), then
    an O(1) lookup (hash table) selects the wire struct. The selected
    struct's decode is zero-copy as before.

** Target protocols
   - ITCH 5.0 full message dispatch (all ~20 message types)
   - Ethernet ethertype dispatch (IPv4, IPv6, ARP)
   - IPv4 protocol dispatch (TCP, UDP, ICMP)

* ACN Completeness Roadmap

  wirey aims to be a complete specification language for binary wire
  protocols, matching the capabilities of ACN (ASN.1 Control Notation)
  in Racket-native form. The following versions close the remaining
  gaps between wirey and what ACN can express.

* v0.8 — Bit Ordering

** Goal
   Support both MSB-first and LSB-first bit packing, with a four-level
   override hierarchy matching how ~#:byte-order~ already works.

** Design

*** Override hierarchy (most specific wins)
    1. *Global default*: MSB-first (matches network convention)
    2. *Per-protocol*: ~#:bit-order msb~ or ~#:bit-order lsb~ on ~struct/wire~
    3. *Per-group*: ~#:bit-order~ on the first field of a bitfield group
       (applies to the entire contiguous group)
    4. *Per-field*: ~#:bit-order~ on an individual bit-unit field

*** Syntax
    #+begin_src racket
    ;; Protocol-level default
    (struct/wire usb-descriptor
      #:byte-order little
      #:bit-order lsb
      (ep-number  uint 4 #:unit bits)
      (reserved   uint 3 #:unit bits)
      (direction  uint 1 #:unit bits)
      ...)

    ;; Per-field override within an MSB-default protocol
    (struct/wire mixed-bits
      #:byte-order big
      (msb-field  uint 4 #:unit bits)
      (lsb-field  uint 4 #:unit bits #:bit-order lsb))
    #+end_src

*** Encoding
    - MSB-first (current): bits shift left, fill from high bit
    - LSB-first: bits shift right, fill from low bit
    - Within a bitfield group, all fields must agree on bit order
      (or be explicitly overridden). Mixed bit orders within a single
      byte require explicit field-level annotation.

*** Impact
    - ~field-desc~ gains ~#:bit-order~ (default ~#f~ = inherit)
    - Bitfield group collection resolves effective bit order per group
    - Encode/decode bit accumulation direction depends on bit order
    - Existing code unchanged (MSB-first remains the default)

*** DONE Step 1: ~#:bit-order~ in field-desc
    - field-desc gains bit-order field (~'msb~, ~'lsb~, or ~#f~ for inherit)
    - ~bit-order?~ predicate
    - Validation: only allowed on bit-unit fields

*** DONE Step 2: Bitfield group bit-order resolution
    - Groups split on bit-order change (not just byte/bit boundary)

* v0.9 — Alignment and Padding

** Goal
   Support alignment constraints and explicit padding, so fields can
   be aligned to byte, word (16-bit), dword (32-bit), or arbitrary
   boundaries. Many protocols require fields to start at aligned
   offsets, with padding bytes inserted between fields.

** Design

*** Alignment declaration
    #+begin_src racket
    (struct/wire aligned-msg
      #:byte-order big
      #:alignment 4               ; default: align fields to 4-byte boundaries
      (tag    uint 1)
      (pad    padding 3)          ; explicit padding (3 bytes)
      (value  uint 4)
      (short  uint 2)
      (auto   padding #:align 4)  ; auto-pad to next 4-byte boundary
      (data   uint 4))
    #+end_src

*** Padding field type
    A new field type ~'padding~ that:
    - Encodes as zero bytes
    - Decodes as ignored bytes (not included in accessors)
    - Can have a fixed width or ~#:align N~ to auto-compute width

*** Auto-alignment
    ~(padding #:align N)~ computes the number of padding bytes needed
    to bring the current offset to the next N-byte boundary.
    Width = ~(N - (current-offset mod N)) mod N~.

*** Protocol-level alignment
    ~#:alignment N~ on ~struct/wire~ inserts implicit padding before
    each field to align it to an N-byte boundary. Individual fields
    can opt out with ~#:no-align~.

*** DONE Step 2: Auto-alignment padding

* v0.10 — Conditional Presence

** Goal
   Support fields that are present or absent based on the value of
   another field. ACN calls this ~present-when~. Essential for
   protocols where optional fields or variant structures depend on
   flags or type indicators.

** Design

*** Conditional field declaration
    #+begin_src racket
    (struct/wire optional-msg
      #:byte-order big
      (flags    uint 1)
      (payload  uint 4 #:present-when (λ (fields) (bitwise-bit-set? (fields 'flags) 0)))
      (extra    uint 2 #:present-when (λ (fields) (bitwise-bit-set? (fields 'flags) 1))))
    #+end_src

    ~#:present-when~ takes a predicate over a lookup function.
    At decode time, if the predicate returns ~#f~, the field is
    skipped (not decoded, accessor returns ~#f~ or a sentinel).

*** Encoding
    - If a field's presence predicate evaluates to ~#f~ based on the
      provided values, the field is not encoded (zero bytes).
    - The presence predicate is evaluated against the encode values hash.

*** Decoding
    - Fields decoded sequentially. When a conditional field is reached,
      the predicate is evaluated against already-decoded fields.
    - If absent: offset does not advance, accessor returns ~#f~.

*** Impact on variable-length
    Conditional fields are implicitly variable-length (0 or full width).
    Total size depends on which fields are present.

    - struct/wire parses ~#:present-when expr~

*** DONE Step 2: Conditional encoding
    - Evaluate presence predicate against values hash
    - Skip encoding absent fields (0 bytes)
    - Total size computed dynamically for conditional protocols
    - Contract validation skips absent fields

*** DONE Step 3: Conditional decoding
    - Evaluate predicate against decoded-so-far
    - Absent fields: offset unchanged, accessor returns #f
    - Boundary vector stores ~'absent~ marker for absent fields

* Self-Describing Format Support

  wirey aims to be a complete specification language for all binary wire
  formats. The following extensions close the gap for self-describing
  recursive formats like CBOR, ASN.1 BER/DER, Protocol Buffers, and
  MessagePack.

* v1.1 — Case Dispatch Within a Struct

** Goal
   Select among different field layouts based on a previously decoded
   field's value. This is the intra-struct equivalent of ~define-dispatch~.
   Required for CBOR's major-type/additional-info branching, ASN.1 BER
   tag-driven structure, and Protocol Buffers wire types.

** Design

*** Syntax
    #+begin_src racket
    (struct/wire cbor-item
      #:byte-order big
      (major-type       uint 3 #:unit bits)
      (additional-info  uint 5 #:unit bits)
      (#:case additional-info
        [((λ (v) (<= v 23)))
         ;; Value is inline — no extra fields
         ]
        [(24)
         (value uint 1)]
        [(25)
         (value uint 2)]
        [(26)
         (value uint 4)]
        [(27)
         (value uint 8)]))
    #+end_src

*** Semantics
    - ~#:case field-name~ introduces a case block after a discriminator field
    - Each branch ~[(predicate-or-value) field-spec ...]~ adds fields
      conditionally based on the discriminator's decoded value
    - Branches are tried in order; the first match wins
    - Values can be exact matches or predicate functions
    - Only one branch is active at a time
    - Fields in the active branch are accessible by name
    - Fields in inactive branches return ~#f~

*** Encoding
    - The encoder determines which branch to use by examining the
      discriminator value in the provided keyword args
    - Only the active branch's fields are encoded

*** Decoding
    - After decoding the discriminator, evaluate branch predicates
    - Decode only the matching branch's fields
    - Non-matching branches' fields return ~#f~ from accessors

*** Impact
    - This generalizes ~#:present-when~ (which is a binary case)
    - Multiple ~#:case~ blocks can appear in one struct
    - Branches can contain nested ~#:case~ blocks (for multi-level dispatch)

*** DONE Step 2: Case-aware encoding
*** DONE Step 3: Case-aware decoding

* v1.2 — Recursive Types

** Goal
   Allow wire structs to reference themselves or other wire structs as
   repeated element types. Required for CBOR arrays (which contain CBOR
   items), ASN.1 constructed types, Protocol Buffers nested messages,
   and any TLV format where the value is itself a TLV structure.

** Design

*** Recursive field references
    #+begin_src racket
    (struct/wire cbor-item
      #:byte-order big
      (major-type       uint 3 #:unit bits)
      (additional-info  uint 5 #:unit bits)
      (#:case major-type
        [(4)  ;; Array
         (items cbor-item #:repeat (decoded-value additional-info) #:struct)]
        [(5)  ;; Map
         (pairs cbor-map-entry #:repeat (decoded-value additional-info) #:struct)]
        ...))
    #+end_src

*** Self-referencing types
    - A struct/wire can reference its own name in a field type
    - Decoded recursively: each nested instance is decoded at the
      appropriate offset, producing a tree of struct instances
    - The recursion terminates when a non-recursive branch is reached
      (e.g., CBOR integer, string, or simple value)

*** Representation
    - Decoded recursive structures are trees of wire struct instances
    - Accessors on array fields return lists of wire struct instances
    - Tree depth is bounded by the data (not by the type definition)

*** Encoding recursive values
    - Accept nested Racket structures (lists of structs, etc.)
    - Or accept pre-encoded bytes for leaves
    - Encode depth-first

*** Impact
    - ~#:struct~ already handles embedded structs
    - ~#:repeat~ already handles arrays of fixed types
    - Combining them enables ~#:repeat~ of ~#:struct~ fields
    - Self-reference is the new capability

* v1.3 — CBOR Specification

** Goal
   Define CBOR (RFC 8949) completely in wirey, as a proof that the
   language can describe self-describing recursive formats.

** Design
   CBOR requires the features from v1.1 (case dispatch) and v1.2
   (recursive types). The specification consists of:

   1. ~cbor-head~ — initial byte (major type + additional info)
   2. ~cbor-value~ — multi-way case dispatch for value encoding
   3. ~cbor-item~ — combines head + value, recursive for compound types
   4. ~cbor-array~ — repeated cbor-item
   5. ~cbor-map~ — repeated key-value pairs of cbor-items

* The CBOR Problem

  v1.3 implemented CBOR as a hand-written encoder/decoder that uses
  wirey's codec primitives directly. This proves the primitives are
  useful building blocks, but it does NOT prove that wirey's DSL can
  describe self-describing recursive formats.

  The goal was always that wirey should be a complete specification
  language. If CBOR cannot be expressed through ~struct/wire~, the
  language is incomplete. The hand-written CBOR module should be
  replaced by a ~struct/wire~ definition.

** What CBOR needs from ~struct/wire~ that doesn't work today

   Target definition:
   #+begin_src racket
   (struct/wire cbor-item
     #:byte-order big
     (major-type       uint 3 #:unit bits)
     (additional-info  uint 5 #:unit bits)
     (#:case additional-info
       [((λ (v) (<= v 23)))]
       [(24) (argument uint 1)]
       [(25) (argument uint 2)]
       [(26) (argument uint 4)]
       [(27) (argument uint 8)])
     (#:case major-type
       [(0)] [(1)]
       [(2) (payload octets (field-ref argument))]
       [(3) (payload octets (field-ref argument))]
       [(4) (items cbor-item
              #:repeat (field-ref argument) #:struct)]
       [(5) (pairs cbor-item
              #:repeat (compute (* 2 (field-ref argument)))
              #:struct)]
       [(6) (content cbor-item #:struct)]
       [(7)]))
   #+end_src

*** Gap 1: Variable-length fields inside ~#:case~ branches
    Today, ~#:case~ branch fields are parsed as normal field clauses,
    but the codec path for case-block protocols uses ~decode~ + ~hash-ref~.
    The low-level ~decode~ handles variable-length fields (it evaluates
    ~field-ref~ and ~compute~ width expressions). So the codec already
    supports this — but the ~struct/wire~ macro doesn't pass ~field-ref~
    width expressions through case branch parsing correctly.

    *Fix*: Ensure ~parse-normal-field~ in case branches produces
    field-descs with proper ~field-ref~/~compute~ widths, and that
    the codec's case-block handling evaluates them.

*** Gap 2: ~#:struct~ and ~#:repeat #:struct~ inside ~#:case~ branches
    Today, ~#:struct~ and ~#:repeat ... #:struct~ are parsed as special
    field clause patterns at the top level of ~struct/wire~. They are not
    recognized inside ~#:case~ branch field lists because
    ~parse-normal-field~ doesn't handle them.

    *Fix*: Extend ~parse-normal-field~ (or the case branch parser)
    to recognize ~#:struct~ and ~#:repeat ... #:struct~ patterns.
    The accessor generation for case-block protocols already uses
    ~decode~ + ~hash-ref~, so the codec needs to handle these field
    types within case branches.

*** Gap 3: Cross-case field references
    CBOR has two ~#:case~ blocks in sequence. The second (~#:case major-type~)
    references ~argument~ which is defined in a branch of the first
    (~#:case additional-info~). This means:

    - ~argument~ may or may not exist depending on which branch of the
      first case was active
    - When ~additional-info <= 23~, there is no ~argument~ field;
      ~additional-info~ itself IS the argument
    - The second case's ~(field-ref argument)~ must resolve to either
      the explicit ~argument~ field or fall back to ~additional-info~

    This is the hardest gap. It requires:
    a. The codec to evaluate ~field-ref~ against the decoded hash,
       which includes fields from active case branches
    b. A way to express "use ~argument~ if present, else ~additional-info~"
       — this could be a ~compute~ expression:
       ~(compute (λ (lk) (or (lk 'argument) (lk 'additional-info))))~

*** Gap 4: Recursive ~#:struct~ inside case branches
    ~(content cbor-item #:struct)~ inside a case branch requires the
    codec to call ~cbor-item-decode~ recursively. The self-reference
    works at define time (Racket resolves it lazily in lambda bodies).
    But the codec's case-block handling would need to recognize
    embedded/repeated struct fields within branch field-descs and
    invoke the appropriate decode functions.

    Currently, embedded structs are handled at the ~struct/wire~ macro
    level by generating custom accessors. For case-block protocols,
    the accessor uses ~decode~ + ~hash-ref~. So the codec's ~decode~
    function needs to handle embedded struct decoding within case
    branches — which it currently doesn't.

*** Gap 5: Indefinite-length encoding
    CBOR's indefinite-length mode (~additional-info = 31~) uses a
    break sentinel byte (~0xFF~) to terminate sequences. This is
    similar to ~#:repeat-until~ but the repeated elements are
    themselves ~cbor-item~ instances (variable-width, recursive).

    This combines Gap 2 (repeated structs in case branches),
    Gap 4 (recursive struct references), and ~#:repeat-until~.

* v2.0 — Full-Power Case Branches

** Goal
   Make ~#:case~ branches support the full feature set of ~struct/wire~
   fields: variable-length (~field-ref~, ~compute~), embedded structs
   (~#:struct~), repeated structs (~#:repeat #:struct~), and
   ~#:repeat-until #:struct~. This enables CBOR to be expressed
   entirely through the DSL.

** Design Principles
   - The codec (~decode~/~encode~) is the ground truth. If the codec
     can handle a feature, ~struct/wire~ should be able to generate it.
   - Accessors for case-block protocols use ~decode~ + ~hash-ref~.
     This means all features must work at the codec level within
     case branches — the macro just needs to generate correct
     field-descs and case-blocks.
   - Self-referencing types work through lazy lambda captures.
     The codec calls decode functions that are defined after the
     protocol-desc is constructed.
